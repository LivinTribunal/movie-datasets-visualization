# X3: extra film data in the app

Spec: `docs/superpowers/specs/2026-11-16-extra-data-design.md` §3 (data
contract) and §4 (what the app shows). Decision D33.

Rules: mirror the nearest code in each file and the existing look (tokens in
`app/src/index.css`, card styles in `views/FilmCard/filmcard.css`), minimal
diff, no new dependency, no `any`. No tree-changing git. Do not run the full
test suite, the build or e2e: `npx tsc --noEmit`, `npx eslint <your files>`
and `npx vitest run <your test files>` in `app/` only. Stop after about 45
turns and report what is left.

The packs are regenerated by another worker at the same time, so
`app/public/data` does not have the new columns yet. Code against the
contract; the architect regenerates the data and runs the app.

Files (only these, all under `app/src/`): `lib/types.ts`, `lib/data.ts`,
`lib/measures.ts`, `lib/measures.test.ts`, `lib/filter.ts`,
`lib/filter.test.ts`, `lib/hash.ts`, `lib/hash.test.ts`, `state/store.ts`,
`views/FilterBar/FilterBar.tsx`, `views/FilmCard/FilmCard.tsx`,
`views/FilmCard/filmcard.css`, `state/selectors.ts` (the only `filmMask` caller), `lib/film.ts` (+ its test) if a helper belongs
there. Test fixtures that build a `Films` object must get the new columns.

## 1. Types and loading

- `Films` gains `story_source`, `story_source_src`, `age_rating`, `studio`
  (DictColumn), `opening_usd`, `opening_usd2025`, `legs`, `video_usd2025`,
  `theaters`, `oscar_wins`, `oscar_noms` (Float64Array, NaN = null). Flag bit
  5 is `numbers_fuzzy`; update the `flags` doc comment.
- `Meta` gains `detail: { shard_size: number; shards: number }`.
- `FilmsDetail` (one shard): `overview, cast, writers, companies, qid,
  csfd_id, filmaffinity_id, allocine_id, douban_id`, each `(string|null)[]`.
- `data.ts`: decode the new columns exactly as the existing dict and numeric
  ones are decoded. Add `loadDetail(row, meta)` that returns
  `Promise<{ shard: FilmsDetail; index: number } | null>`: null when
  `row >= shards * shard_size`; otherwise fetch
  `data/films_detail_${Math.floor(row / shard_size)}.pack` once (memoise the
  promise per shard, like `loadText`).

## 2. Measures

Add to `MeasureKey`/`MEASURES`/`COLUMN`:
- `opening`: label "opening weekend, US", short "Opening", money unit, log;
  `measureColumn` returns `opening_usd2025` or `opening_usd` by the money
  toggle, and `axisLabel` treats it like budget and revenue.
- `theaters`: "widest release", "Theatres", unit "theatres", linear.
- `legs`: "legs, US gross ÷ opening weekend", "Legs", "×", log.
- `oscar_noms`: "Oscar nominations", "Oscar noms", "count", linear.
Extend `measures.test.ts`. The scatter and table read `MEASURE_KEYS`, so they
pick these up; check that nothing there assumes the old list length.

## 3. Filters

- Store: `story: 'any' | StoryCategory` (the seven §3 values) and
  `studio: 'any' | 'major' | 'independent'`, defaults `'any'`, setters
  `setStory`, `setStudio`; `reset` restores them.
- `FilmFilter` and `filmMask`: a film with `story !== 'any'` passes only if
  its `story_source` equals it; `major` passes any studio code except
  `independent` and null; `independent` passes only `independent`. Read the
  dict code once outside the loop, like the country codes. Pass the two
  values wherever `filmMask` is called with the store's filter (grep the
  callers; add them there).
- Hash: keys `st` and `stu`, encoded only when they differ from the base,
  decoded only for known values. Tests for both in `hash.test.ts` and
  `filter.test.ts`.
- FilterBar: in the row with subset and money, a `select` "story" (`any
  story`, `original`, `book`, `comic`, `true story`, `stage`, `film/TV`,
  `other`) and a segmented control "studio" (`any`, `major`, `indie`), using
  the same components and classes as the existing subset and money controls.

## 4. Film card

After the money group, a "release" group in the same row style as money
(`fc-money`, `fc-label`, `fc-value`, `fc-badge`), rows shown only when the
value exists, and the group hidden when no row has a value:

- age rating (US); story source in words, badge "from TMDB keywords" when
  `story_source_src` is `tmdb`; studio (display names: Disney, Warner Bros.,
  Universal, Sony, Paramount, 20th Century Fox, Lionsgate, MGM, independent).
- opening weekend with `fmtMoney` and the same unit and badges logic as the
  money rows (inflation-adjusted under 2025 USD), plus badges "US only",
  "source: The Numbers", "fuzzy title match" when flag bit 5 is set.
- widest release `fmtInt(theaters)` theatres; legs `fmtRatio`; home video
  (2025 USD) with badge "estimate".
- Oscars: "N wins of M nominations", badge "Wikidata"; when M is 0, "none".

Then an "about" group, only for rows inside the detail shards: load with
`useLazy`-style state keyed on the row (show nothing until it resolves, never
a spinner that shifts the layout); overview paragraph; "cast", "written by",
"companies" lines; a links line with Wikidata
(`https://www.wikidata.org/wiki/{qid}`), ČSFD
(`https://www.csfd.cz/film/{id}/`), FilmAffinity
(`https://www.filmaffinity.com/en/film{id}.html`), AlloCiné
(`https://www.allocine.fr/film/fichefilm_gen_cfilm={id}.html`) and Douban
(`https://movie.douban.com/subject/{id}/`), each only when its id exists, as
`target="_blank" rel="noreferrer"` links like the IMDb one.
