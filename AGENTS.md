## What this project is

The PV251 Visualization (FI MUNI, autumn 2026) team project, seminar group 5.
It is an interactive web app that lets users explore how **money**, **critic
and audience ratings**, and **genre taste over time and per country**
(cinemas and Netflix) relate.

- Plan, timeline and visualization draft: `docs/PLAN.md`. Read it first.
- Every dataset, its version, licence, path and status: `DATASETS.md`. Update
  it whenever a source is added or its status changes.
- Design sheets are drawn on paper and scanned into `docs/design-sheets/`
  (`sheet-1.jpg`, …). Describe what a scan shows before you rely on it.
- Decisions and why we made them: `docs/decisions.md`. Add an entry when you
  make a decision that is not obvious.
- Data-and-task analysis we submitted as HW1: `materials/project.md`.
- Team: Štefan Moravík, Matúš Buzgo, Emma Tomášová. The UČOs are kept out of
  the public repo, in the gitignored `team.local.md`. Copy them from there
  into the design sheets and the report.
- Lecture text: `materials/is_export/*.txt` (made from the PDFs). Local
  only: the repo is public, so course material is gitignored.

- Design follows the **Five Design Sheets** method (sheet 1 brainstorm,
  sheets 2–4 three different designs, sheet 5 the final design).
- What we submit: source code, a **deployed link**, a video demo, and a
  report (motivation, data sources and preprocessing, design choices,

  Write code and data notes so they can go straight into that report.

  Imputed, converted, inflation-adjusted or fuzzy-matched values must be

## Data conventions

- **Film key**: `imdb_id` (`tt\d+`). TMDB `id` is a secondary key. Wikidata
  is the hub for the RT, Metacritic, LUMIERE and Wikipedia IDs.
- **Country key**: ISO 3166-1 alpha-2, always mapped through
  `data/reference/countries.csv`, never with ad-hoc name matching in code.
- **Missing** is null, never `0`, `-1` or `""`. TMDB's `0` budget, revenue
  and runtime are recoded to null when the data is cleaned.
- **Money**: store nominal values and `*_usd2025` (FX at the release-year
  average, then CPI `CPIAUCSL` to 2025). Every money column has a source
  column (`budget_src`, `revenue_src`). **Never impute money.**
- **Ratings**: rescaled to 0–100 in columns ending `_100`. Critics: tomatometer and
  metascore. Audience: audience_score, imdb_rating, mc_user_score,
  letterboxd_avg.
  `gap = audience − critics`.
- **Genres**: `genre_weight = 1/n` for shares; full membership for
  distributions per genre. Colours use the ~8 genre families from
  `data/reference/genre_families.csv`.
- **Subsets**: working = Released, 1900–2026, ≥ 1,000 IMDb votes; notable =
  ≥ 10,000 votes. The money tasks use the notable subset.
- Snapshot dates are fixed: TMDB+IMDb **2026-10-01**, Netflix up to
  **2026-09-27**. Do not refresh them without a new entry in
  `docs/decisions.md`.

## Scraping rules

- At most **1 request per second per host**. Send a descriptive User-Agent
  with a contact address. Respect `robots.txt`.
- Every response goes to `data/cache/` first, and parsers read only from the
  cache, so a re-run never hits the network again.
- The data is for non-commercial academic use only. Never commit raw HTML
  or anything from `data/cache/`.
- Scrapers must be resumable: skip IDs that are already cached, and write
  results as you go.
- Scrapers never run in CI.

## Visualization rules

- Position first; colour only for ≤ 8 categories or for one sequential or
  diverging quantity.
- No rainbow palettes, no red–green diverging palettes, no 3D. Use
  ColorBrewer / Okabe–Ito. Encode categories a second way (label, shape)
  wherever you can.
- Money axes are log scale and say so; every axis label has its unit and
  the year of the USD.
- Countries with no data are drawn hatched, never in a colour from the
  scale.
- The scatter renders on canvas (~25k points); everything else uses SVG
  rendered by React, with D3 for the maths (scales, shapes, geo, brushing,
  zoom).
- Shared filter and selection state lives only in the zustand store. Views
  read from it and write to it; views never talk to each other directly.

## Code style

- Python: `ruff` (lint + format), type hints, polars over pandas, pure
  functions per stage (input files → output files).
- TypeScript: strict mode, ESLint, functional React components, no `any`
  in data types. The data types live in `app/src/lib/types.ts` and mirror
  the schema that `movies export` writes.
- Tests: pipeline transformations get pytest cases on small fixtures. App
  helpers (scales, aggregations) get Vitest cases. Do not write tests that
  need the network or the full raw data.
- Before writing or changing code, find the nearest existing example of the
  same kind of thing and mirror its shape, location and naming. Reach for the
  laziest solution that works: reuse an existing helper, extend a sibling,
  polars, D3 or the stdlib before new code or a new dependency. Keep the diff
  minimal, no drive-by refactors. Close with one line naming the exemplar you
  mirrored. Full rules in `.claude/skills/grain/`.

## CI

GitHub Actions on every push and PR. Jobs:
1. `pipeline`: ruff, pytest, `movies validate` on the committed app data.
2. `app`: lint, type check, vitest, vite build.
3. On `main` (optional): deploy `app/dist` to GitHub Pages.

**Hosting: mainly local, also GitHub Pages (free).** The app is a static
build that must work from any static file server, so keep Vite's `base: './'` (relative
paths), load data with relative URLs, and use no host-specific features
(no server routes, no Pages-only redirects; use hash routing if routes are
needed). The build must not depend on `data/raw/` or the network. If you change the
export schema, update `app/src/lib/types.ts` and the validator in the same
change.

## Git

- Branch from `main`, open a PR, CI must pass before merging.
- Commit messages: start with a verb, lowercase, short
  (`add wikidata crosswalk`).
- Before pushing, self-review the diff (`.claude/skills/pr-ready/`). Review a
  teammate's PR by proving each finding with a failing test before fixing it
  (`.claude/skills/review-proof/`).
- Never commit `data/raw/`, `data/cache/`, `data/interim/`, course PDFs, the
  IS HTML pages, API keys or `.env`.
- Keys (`KAGGLE_*`, `TMDB_API_KEY`) go in `.env`, which is gitignored;
  `.env.example` lists them.
